## 試験時の注意
- 未固定なので **出力段階 LOW のみ**で試験する。トルクの反力で筐体ごと回る可能性がある
- ハンドルの回転範囲の近くにキーボードがある → 初回は低速(≤ 1 rad/s)・小角度から
- 1 A 電源: 急加速・急減速で電源が電流制限にかかると電圧降下 → 低電圧故障(< 12 V)の可能性。LOW の電流制限(1 A)内なら問題ない見込み
- 外力でハンドルを回すと発電して電源側に回生する(24 V 電源なので過電圧 60 V までは余裕がある)
- モータを動かす試験は、ユーザーの了承を得てから行う

### 2026-10-02 HW-2 第 1 回: 速度モード 0.5 rad/s × 5 s(LOW、CLI、Opus)
- 結果: **回転は正常**。位置 2.038 → 4.029 rad(運転中の最終表示)、速度 0.42–0.52 rad/s で 0.5 rad/s に追従、トルク ≤ 0.10 N·m、温度 29.0 ℃ のまま。カメラでハンドルが約 145° 回ったことを確認(停止後の位置 4.538 rad と一致)。筐体は動かず
- 正方向: 出力面を上から見て、ハンドルが画面右下 → 左へ(カメラ視点)。回転方向の定義(CW/CCW)は 3D 表示の `ROTOR_SIGN` 確認時に詰める
- 受信レート: 主動上報 + type 18 応答で約 190 Hz
- **不具合**: 終了時に運転停止が効かず spd_ref = 0.5 の送信が続き、無効化の確認に失敗(exit 1)。Session.close の stop で停止するまで約 1 s(≈ 0.5 rad)惰走。受信フレームの時刻が記録されていない。→ 修正済み(phase2-fix。実機での再確認待ち)
  - **根本原因(実測で確認)**: `--log` を共有フォルダ(SMB)に置くと、行バッファの 1 行書込みが約 3 ms(ローカルは 0.004 ms)。BusManager の TX スレッド(TX ロック内)と RX スレッドが同期でこのログを書くため、約 200 TX + 約 300 RX 行/s で処理能力を超え、TX キューに古い spd_ref が滞留(MAX_BACKLOG 64 = 最大約 0.3 s 分)・RX は約 0.7 s 遅れた。RX のタイムスタンプは「読出したチャンクの時刻」で、148 フレームが同一時刻になっていた(= RX スレッドの遅れ。ログの同一時刻はその症状)
  - その結果: (1) 停止指令・保持指令が古い指令の後ろ(同じ CONTROL 優先度の FIFO)に並び、一度も送られなかった(ログに spd_ref = 0 が 0 件)。(2) type 4(ESTOP 優先度)は先に出るが、後ろの古い spd_ref が続いて送られた。(3) 無効化の確認は「type 4 の後に最初に処理した type 2」を見たが、それは遅れて処理された古い応答(mode=MOTOR)で、再送を 3 回使い切って失敗。ログの受信フレームが停止後も MOTOR なのは RX の遅れによる(古いフレーム)
  - 修正: フレームログを非同期書込み(専用スレッド)に。AT トランスポートに読取りスレッドを置き、受信時刻をその場で付与。TX キューの CONTROL 指令をモータ単位で破棄(`BusManager.purge_control`)。停止(detach)は破棄後に on_stop を ESTOP 優先度で送出。無効化は `ControlLoop.inhibit`(同期・以後 enable まで指令なし)。無効化の確認は「type 4 の実送信時刻以降に受信した Reset」(`Motor.is_reset_since`)で、満たさなければ type 4 を再送(最大 4 回)。`stop_motion` はどの状態でも冪等(コントローラ / keepalive が残っていれば外して保持)。MAX_BACKLOG は 16 に縮小
  - 教訓: 実機ログは**ローカルディスク**(`%LOCALAPPDATA%` など)に出すのが望ましい(非同期化後も共有フォルダは遅い)
- 生ログ: `user_data/hw2_velocity.log`

### 2026-10-02 送信間隔と取りこぼし(読み出し専用 type 17、Opus)
16 個の type 17 を連続送信して応答数を数えた(`EL05 ID 127` + 公式 USB-CAN、921600 bps)。

| 送信方法 | 間隔 | 応答 / 送信 |
|---|---|---|
| `send_many`(1 write に連結) | 0 | 2/2, 2/4, 4/8, 6/16 |
| 個別 write | 0 ms | 5/16, 7/16 |
| 個別 write | 0.2 ms | 6/16, 7/16 |
| 個別 write | 0.5 ms | 15/16, 16/16 |
| 個別 write | 1.0 ms / 2.0 ms | 16/16 |

- **フレーム間隔 0.5 ms 未満で取りこぼす**(アダプタ側かモータ側かは未切り分け)。**送信側で最小 1 ms の間隔を空ける**(AtSerialTransport の送信ペーシング)。→ 送信上限は約 1000 フレーム/s。1 台 200 Hz 制御 + ポーリングは余裕、3 台 × 200 Hz でも可。高周期・多台数は CANHUB 等の別アダプタを検討(can_transport.md §4 の計算より厳しい実測制約)
- HW-2 再試験(phase2-fix 後)で、有効化手順の書込み(0.2 ms 間隔)の応答が欠落してタイムアウトしたのはこれが原因。修正前は共有フォルダへの同期ログが偶然 2.5 ms 間隔を作っていた
- 主動上報周期: EPScan_time = 0 → 10 ms、**= 1 → 15 ms**(実測)。マニュアルの「1 = 10 ms」とずれており、**周期 = 10 + 5·N ms** が実機の挙動
- 対策(phase2-fix): `AtSerialTransport(min_frame_gap_s=0.001)` で書込み間隔を強制、`send_many` は連結しない。EPScan_time の変換は N = (周期 − 10) / 5(主動上報 10 ms は N=0 を書く)
- 確認(読み出し専用、ペーシング後): `params 127` は 28 項目中 25 項目を読出し(読出不可は既知の 3 項目)。EPScan_time の現在値は 1、`monitor` の受信は 67 Hz(= 15 ms 周期 = 10 + 5·1 と一致)。canTimeout の現在値は 5000(profile 既定は 0)

### 2026-10-02 主動上報中の応答欠落(読み出し専用 type 17、5 ms 間隔 × 200、Opus)
| 条件 | 応答 / 要求 |
|---|---|
| 主動上報 OFF | 200/200, 200/200 |
| 主動上報 ON(10 ms) | 191/200, 188/200(約 5 % 欠落。上報フレーム自体は 210/210 届く) |

- **モータが主動上報フレームを出すタイミングと重なると、要求への応答が失われる**(モータ側かアダプタ側かは未切り分け)
- HW-2 の JOG 逆転が開始前にタイムアウトしたのはこれ(limit_torque 書込みの type 2 応答が欠落)
- 対策: (1) 冪等な要求(読出・書込・有効化・停止)は自動で再送、(2) 有効化手順や運転中は主動上報を OFF(運転中は制御ループの type 1/18 への応答で 200 Hz のフィードバックが得られる)、待機中の監視だけ ON
- 停止時: 速度 0 指令 → 無効化の間隔が短く、無効化後に約 0.06 rad 惰走した → 減速を待ってから無効化する
- 実装(phase2-fix): (1) `Motor` の冪等な要求(read/write/enable/disable/set_run_mode/set_active_report/get_uid)は `retries`(既定 2 = 計 3 回)再送。`motor.retry` イベント・`BusStats.retries` で数える。set_zero/save は再送しない。(2) `MotorService` は無効(監視)中だけ主動上報 ON、`enable()` の最初に OFF、運転中は OFF(`report_while_enabled=False`)、無効化完了・故障・通信断・E-STOP 後に ON。(3) `stop_and_disable`(CLI 運動コマンドの終了処理)は運転停止 → |速度| < 0.05 rad/s(最大 0.5 s)→ 無効化。E-STOP は待たない。シミュレータは `reply_drop_rate`(応答だけ欠落、主動上報は除く)で再現。実機での効果(惰走量・再送回数)は未確認

### 2026-10-02 HW-3b 位置の折り返し(速度モード 0.3 rad/s、LOW、CLI、Opus)
- 動機: シミュレータで、多回転位置が 4π を超えた状態で MIT 運転を止めると、位置保持(HoldCmd)の目標が 8π ずれて −50 rad/s で引き戻される不具合を発見(K_07 の画面で速度が −8 rad/s に振れていたことから)
