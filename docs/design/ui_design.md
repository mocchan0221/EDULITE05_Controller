- 状態: **v2.0 (2026-10-01)** — UI-1 でのユーザー指摘「配色・配置・サイズ・アフォーダンスが弱く煩雑、何を操作すればどうなるか分かりにくい」を受けた作り直し

## 1. 利用者と作業

利用者: モータを机上で試す技術者(本ツールの作者自身を含む)。CAN やモータ制御の知識はあるが、**画面を見た瞬間に「今どういう状態で、次に何を押せばよいか」が分かる**ことを求める。実機は通常 1 台、ときに 2–3 台。

| # | 作業 | 頻度 | v1 の問題 |
|---|---|---|---|
| T1 | 接続: アダプタを選んで接続、モータを見つける | セッション毎に 1 回 | 接続設定が常に左上の一等地を占有。接続後も全項目が残る |
| T2 | とりあえず回す(JOG・速度) | 最多 | 有効化/停止がツールバー、開始/停止が制御パネルにあり、どれが何を止めるか不明 |
| T3 | モード試験: 目標を設定 → 開始 → グラフで指令と実測を比較 | 多 | モードがタブなので「見ているタブ」と「動いているモード」がずれる |
| T4 | MIT(インピーダンス)で手応えを確かめる | 中 | 5 つのスライダ + 謎の「0」ボタン + 数式の説明文で読み取りにくい |
| T5 | パラメータを確認・調整・保存 | 中 | 一時書込と Flash 保存の区別が色だけ。編集行の塗りが重い |
| T6 | 異常に気づき、原因を知り、復帰する | 低(重要) | 正常時に緑ランプ 6 個が最も目立ち、異常が埋もれる |
| T7 | 保守(ID 変更・ゼロ点・ボーレート・プロトコル) | 稀 | 無害な設定と危険な操作が同じ見た目で並ぶ |
| T8 | 複数台・2 台連動 | 低 | グラフの色が「量」を表しており、モータ 1 と 2 が同じ色 |

## 2. 設計原則(この順で優先)

1. **平常時は静か、異常時だけ目立つ**(ISA-101)。画面の基調は無彩色のグレー。色は「危険・異常・注意が必要」と「操作できる主ボタン/選択中」にだけ使う。
2. **状態と操作を見た目で分ける**。押せるものだけがボタンの形(面・枠・ホバー)を持つ。状態表示はアイコン+文字のバッジで、押せない・ホバーしない。
3. **1 つの場面に主な操作は 1 つ**(GNOME / Fluent / Apple)。強調色のボタンは 1 画面区画に 1 つまで。主ボタンは常に同じ位置にあり、状態に応じてラベルが変わる。
4. **状態を先に、詳細は後に**(要約 → 詳細、段階的開示)。普段使わない設定は折りたたむか別ページへ。
5. **何が起きるかを言葉で示す**。ボタンは動詞で結果を言う(「有効化」「運転開始」「モータに保存…」)。内部用語(run_mode 番号、type 番号、数式)は既定で隠し、ツールチップ/詳細に置く。
6. **できないことは押せなくして理由を言う**(押させてから警告しない)。
7. **色だけに頼らない**。状態は「アイコン+文字+色」、グラフは「凡例+直接ラベル+線種」。
8. **一貫性**。同じ意味は同じ見た目・同じ言葉・同じ場所。モータの色はカード・凡例・グラフ・3D で共通。

## 3. 状態モデルと主ボタン

モータごとの UI 状態(`MotorViewState.ui_state`):

| ui_state | 表示(バッジ) | 主ボタン(インスペクタ下部の同じ位置) | 副ボタン | モード選択 |
|---|---|---|---|---|
| `offline` | ○ 未接続(グレー) | — (「接続…」を案内) | — | 不可 |
| `disabled` | ○ 停止中(グレー) | **有効化**(強調色) | — | **可** |
| `enabled` | ◉ 有効(青系の文字のみ) | **運転開始**(強調色)/ JOG のときは押下保持ボタン 2 つ | 無効化 | 不可(「無効化すると切替できます」) |
| `running` | ▶ 運転中(緑) | **運転停止**(通常ボタン、強調色ではなく枠付き) | 無効化 | 不可 |
| `fault` | ⚠ 故障(赤) | **故障をリセット**(原因表示の後) | — | 不可 |

全体状態:
- **非常停止ラッチ中**: 全操作不可。赤い全幅バナー「非常停止中 — 全モータの出力を止めました」+ [非常停止を解除…]。解除は確認ダイアログ(「安全を確認しました」チェック必須)の 2 段階で、解除後も全モータは `disabled` のまま(自動再開しない)。非常停止で出力段階は LOW に戻る。
- **出力段階 HIGH**: 琥珀色の常設バナー「高出力モード — モータを固定して使用してください」+ [低出力に戻す]。
- **通信断**: 赤バナー「アダプタとの通信が途絶えました」+ [再接続]。全モータ `offline`、HIGH → LOW。

用語を固定する:
- 「有効化 / 無効化」= モータの出力を ON/OFF(type 3 / type 4)
- 「運転開始 / 運転停止」= 指令の送出を開始/停止(運転停止は目標を 0 や現在位置にして止め、有効のまま保持)
- 「非常停止」= 全モータを即無効化 + ラッチ(ソフトウェア停止であり、物理的な電源遮断の代わりではない旨をツールチップに明記)
- 「停止」単独の語は使わない

## 4. 画面構成(情報アーキテクチャ)

```
┌ ヘッダー 56px ────────────────────────────────────────────────────────────────┐
│ EL05 Controller  [● COM7 接続中 ▾]   [■ID1 運転中] [■ID2 停止中] [+]     出力 [低|高]  [■ 非常停止 Esc] │
├ バナー領域(必要時のみ。非常停止 > 故障 > 通信断 > HIGH > モック/シミュレータ)────────────┤
├ナビ┬─ ページ本体 ───────────────────────────────────────────────────────────────┤
│運転│                                                                            │
│パラ│                                                                            │
│診断│                                                                            │
│保守│                                                                            │
│    │                                                                            │
│設定│                                                                            │
├────┴ ステータスバー 24px: 送信 400/s 受信 400/s | 制御 200 Hz ジッタ 0.3 ms | モック ┤
```

- **ヘッダー**(全ページ共通 = ISA-101 のレベル 1: 全体の状況が常に見える)
  - 左: アプリ名(14 Semibold)、**接続ボタン**(フラット。`● COM7 接続中 ▾` / `○ 未接続 ▾`)→ 押すと接続ポップオーバー(§5.6)
  - 中央: **モータチップ**(1 台 1 個: モータ色の四角 + `ID1` + 状態バッジ文字)。クリックで操作対象を選択(選択中は下線+背景)。`+` はスキャン。モータ選択はここに一本化し、他の場所に操作対象コンボを置かない
  - 右: **出力段階**のセグメント(`低出力 | 高出力`。LOW 選択時は無彩色、HIGH 選択時だけ琥珀)、**非常停止**ボタン(赤地白文字、高さ 40、幅 ≥ 140、ラベル「非常停止」+ 小さく「Esc」)
- **ナビゲーションレール**(左 72px、アイコン 20px + 文字 12px の縦並び。Fluent NavigationView / GNOME サイドバー)
  - 運転(既定)/ パラメータ / 診断 / 保守 / スクリプト / ― / 設定(最下部)。プラグインのページ(サンプルの三角波など)は `order` に従ってスクリプトの後ろ・設定の上に並ぶ(スクリプト 50 → サンプル 60)
  - 診断に未確認の故障があれば赤い点を付ける
  - ショートカット Ctrl+1..9 = ナビの上からの順(運転 1 / パラメータ 2 / 診断 3 / 保守 4 / スクリプト 5)。6 番目以降はプラグインのページで、ナビの並び順にそのまま続く(同梱のサンプルは Ctrl+6)
- **ドックは廃止**。固定配置 + `QSplitter`(サイズは記憶)。浮動・閉じるボタンのノイズを消す
- **ステータスバー**: 通信統計、制御周期、バックエンド種別(モック/シミュレータ/実機)。色は使わない(テキスト二次色)

## 5. ページ仕様

### 5.1 運転ページ(既定のページ。T2/T3/T4/T8)

```
┌ナビ┬────────── モニタ(可変幅)──────────────────────────────┬─ インスペクタ 360px ─────┐
│    │ 読み値ストリップ(操作対象のモータ)                          │ ID1 EL05 #1      ◉ 有効  │
│    │ ┌位置──────────┐┌速度─────────┐┌トルク────────┐┌温度 28.7℃┐  │                          │
│    │ │ +0.736 rad    ││ −2.07 rad/s  ││ −0.011 N·m   ││電圧 24.0 V│  │ 制御モード                │
│    │ │ 指令 1.000     ││ 指令 −2.00   ││ 指令 0.000   │└──────────┘  │ [JOG][速度][位置][MIT][その他▾]│
│    │ │ ▁▁▁▁◆▁▁▁●▁▁  ││ ▁▁●◆▁▁▁▁▁▁ ││ ▁▁▁▁●▁▁▁▁▁ │              │                          │

│    │ ┌[グラフ|3D]   表示 [標準▾]  時間幅 [10 s▾]   ⏸ 一時停止  ⏺ 記録 ┐ │ 速度          1.00 rad/s ↺│
│    │ │ 位置 [rad]                                      ID1 0.74 ▏│ │ ━━━━━━━●━━━━━━  −5 … 5    │
│    │ │ 速度 [rad/s]                                    ID1 −2.1 ▏│ │ ▸ 制限と加速度             │
│    │ │ トルク [N·m]                                    ID1 −0.01▏│ │                          │
│    │ │ ── 実測  - - 指令    ■ID1 ■ID2(クリックで表示切替)       │ │                          │
│    │ └──────────────────────────────────────────────────────────┘ │ [      運転開始      ] 40px│
│    │ ▸ イベント  12:03:41 ID 1: 速度モードで運転を開始しました          │ [ 無効化 ]                 │
└────┴──────────────────────────────────────────────────────────────┴──────────────────────────┘
```

**読み値ストリップ**(要約。T2–T4 で一番見る場所)
- 4 セル: 位置 / 速度 / トルク / 温度+電圧。セルは同じ寸法・同じ配置(ラベル 12 二次色 → 実測値 28 等幅 → 単位 14 → 「指令 x.xx」12 二次色 → ゲージ)
- **ゲージ**(横バー 6px): 全幅 = 物理レンジ、薄い帯 = 現在の出力段階で許される範囲、◆ 中抜き = 指令、● 塗り = 実測。数値だけでなく「どこにいてどこへ向かうか」が一目で分かる
- 位置セルには rad/deg 切替(小さなセグメント、セル右上)と多回転値(12 二次色)
- 位置セルの見出し行、rad/deg 切替の隣に控えめな **[⊕ 原点に設定]**(アイコン + 文字。枠なし・面なし、ホバーで薄い面。カードが狭いときは文字を省いてアイコンだけ)。
  押すと確認ポップオーバー「現在位置を 0 にします」(有効・運転中なら「先に停止して無効化してから設定します」を琥珀の 1 行で足す)→ [キャンセル] / [原点に設定]。
  実行は `disable`(= `stop_and_disable`)→ 無効化を待つ → `run_tool("set_zero")` → 結果をトースト。
  未接続・故障・非常停止ラッチ中は無効(理由をツールチップ)。ゼロ点を設定すると読み値とグラフの位置は新しい座標になり、
  グラフの位置の線は NaN で切る(0 への跳びを縦線で結ばない)。±4π 付近で MIT の位置保持が減衰のみになる通知(`position_wrap`)の解消にも使う
- 温度+電圧のセルの 3 行目に **「消費電力 推定  ≈ 4.2 W」**(推定のタグは三次色)。バス電流は測っていないため、トルクと速度からの概算
  (`core/telemetry/power.py`: P_in = τ·ω + 1.5·R_ph·(|τ|/Kt)² + P_base。係数は `profiles/el05.toml` の `[power_estimate]` で **未較正**)。
  内訳(機械出力・銅損・基本消費)ごとに約 0.3 s のローパスをかけて表示し、負(回生)は「回生 ≈ x W」と大きさで出す。ツールチップに内訳と「推定」の説明。
  同じ値を telemetry の `m{id}.power_est`(W、kind=derived、生の瞬時値)として記録し、グラフの「すべて」で `m{id}.power`(推定電力 [W])の段に出す。カードの外形は変えない
- 入力が段階上限で丸められているときは、セル内に琥珀の文字で「低出力上限で制限中」

**モニタ**
- 表示切替 `[グラフ | 3D]`(セグメント)。3D はモータを横に並べ、モータ色のリングで識別
- グラフ: 縦に積んだ小さな複数グラフ(1 グラフ 1 物理量)。**色 = モータ**(§7.2)、**実線 = 実測 / 破線 = 指令**
- 表示プリセット `[標準(位置・速度・トルク) / MIT 解析(位置・トルク) / 温度・電圧 / すべて]`。v1 の 14 個のチェックボックスは廃止
- 凡例はグラフ下の 1 行(`── 実測 - - 指令  ■ID1 ■ID2`)。モータの■をクリックで表示/非表示
- **枠を動かさない**: 運転中の通常の操作で、プロット領域の高さが変わってはならない。グラフ下の
  「状態の帯」(3 レーン固定)・「ステップ応答」の 1 行(高さ 28 固定)・凡例の 1 行(高さ 32 固定)は常に場所を確保する。
  ステップ応答の結果が無いときは同じ行に淡い(三次色)「ステップ応答 —」を出し、結果が出たら同じ行に値を出す。
  トリガ・Δ カーソルの表示は凡例行の右側の文字とプロット上のオーバーレイ(レイアウトに影響しない)、FFT の「対象」は
  ツールバーの 1 行内に出る。帯をポップオーバーでオフにする / 表示プリセットを FFT にする、はユーザーの明示的な選択なので高さが変わってよい
- 各グラフ右端に最新値タグ(モータ色の小さな四角 + 値。文字は本文色)
- 格子は横線のみ・ごく薄く。軸ラベルは量と単位
- 一時停止中はマウス位置の縦カーソルを全グラフで同期表示し、各値をツールチップに
- 記録: `⏺ 記録` で CSV 記録開始、記録中は「● 記録中 00:12」(赤い点はこれだけ例外として許可)

**イベント行**(モニタ下端、1 行): 最新のイベントを 1 件表示。クリックで診断ページのイベントログへ

**インスペクタ**(操作。右 360px、ISA-101 レベル 2)
1. 見出し: `ID1 EL05 #1`(16 Semibold)+ 状態バッジ(§3)
2. **制御モード**: セグメント `[JOG] [速度] [位置] [MIT] [その他 ▾]`
   - その他 ▾ = 電流(トルク)/ 試験信号 / 2 台連動(モータ 2 台以上のときだけ表示)
   - 選択中モードは見出しの下に 1 行の平易な説明(例 速度:「指定した速度で回り続けます」、MIT:「ばねとダンパのようにふるまいます」)。数式・run_mode 番号は ⓘ ツールチップへ
   - `disabled` 以外では押せない(ツールチップ「無効化すると切り替えられます」)
3. **目標**: モードの主な目標値だけを大きく(ParamForm 行 §6.4)
   - 位置モード: 先頭に `動き方 [追従(CSP) | 台形(PP)]`、続けて `目標の基準 [1 回転内(最短) | 多回転]`
     - **1 回転内(最短)**(既定): 目標を「目標の角度」(−π〜π。読み値の rad/deg 切替に従い −180°〜180° も)で入力する。
       コアの純関数 `core/control/targets.py` が `p_target = p_multi + wrap(θ − p_multi)`(wrap は [−π, π))で現在の多回転位置から
       最短の等価角へ変換し、コントローラには従来どおり多回転の目標を渡す(JOG などで 400 rad に達していても使える)。
       結果は欄の下の 1 行に「→ +401.20 rad へ(+0.83 rad)」(絶対位置と移動量)。運転開始の瞬間に目標を確定し、
       運転中の角度の変更は即座に反映(ライブ更新)。運転中は基準を切り替えられない
     - **多回転**: 従来どおり多回転の位置(±4π のスライダー)をそのまま指定する
     - 選択はモードごとに `user_data/ui_state.ini`(`operate/target_ref/position`)へ保存する
   - MIT: 先頭にプリセットチップ `[脱力] [ダンパ] [抵抗ゼロ] [ばね] [その場で保持]`(3 列 × 2 行、最後の「その場で保持」は下段の 2 列分。押すと Kp/Kd/摩擦補償/目標を設定。「その場で保持」は現在位置を目標にする。
     「抵抗ゼロ」= Kp 0・Kd 0・摩擦補償 0.03 N·m で、軸の抵抗を PC 側で打ち消して手で軽く回せるようにする)
   - MIT の Kd は **負の範囲**(出力段階の `kd_negative_max`: LOW −0.05 / HIGH −0.2)まで入力できる。スライダーは 0 に目盛りを出し、
     負の Kd と摩擦補償が 0 でない行には「PC 側で計算します。速度が上がりすぎると自動で制動します」を出す(ツールチップに詳しい説明)
   - JOG: 速度 1 項目のみ
   - 試験信号: 対象(位置/速度/電流)、波形 `[正弦 | ステップ]`、振幅、周波数
4. **▸ 制限と加速度**(折りたたみ、既定は閉): 電流制限・加速度・送信周期・連続/単発(MIT)。既定値は出力段階に従う。
   MIT では「摩擦補償 [N·m]」(0〜出力段階の `friction_comp_max`: LOW 0.1 / HIGH 0.3)もここに置く
5. **主ボタン領域**(最下部固定、§3 の表どおり。幅いっぱい 40px)
   - JOG で `enabled` のとき: `[◀ 押している間 逆転] [押している間 正転 ▶]`(各 48px 高、枠付き・押下中は塗り。押下保持であることを示すアイコン)。離す/ポインタが外れる/ウィンドウがフォーカスを失う/通信断で即停止
   - 運転中は目標の変更が即座に反映される(「送信中 200 Hz」を主ボタン上に小さく)

**未接続時**: モニタ領域の中央に空状態「アダプタが接続されていません」+ アダプタ/ポート選択 + [接続](強調色)。接続後に自動スキャンし、0 台なら「モータが見つかりません」+ 確認項目(電源・配線・終端抵抗・ID)+ [再スキャン]。

### 5.2 パラメータページ(T5)

```
[🔍 検索]  [すべて|制御ゲイン|制限|指令|状態|設定]        未書込 2 · 変更済み 3   [モータから読込] [変更を書込](強調) [モータに保存(type 22)…] [⋯]
┌─────┬───────────────┬───────────┬───────────┬──────┬──────────┬────────┐
│ 状態 │ 名称           │ モータの値 │ 新しい値   │ 単位 │ 範囲      │ 既定   │
│  ✎  │ 速度ループ Kp   │ 6.000     │ [ 8.000 ] │      │ 0 – 200   │ 6     │
│     │  spd_kp 0x701F │           │           │      │           │       │
```
- 状態列アイコン: なし = モータと一致 / ✎ = 編集中(未書込)/ ● = 変更済み(0x70xx は電源を切ると工場値に戻る。実測 HW-6)。行全体の塗りは使わない
- 「新しい値」は編集時のみ値が入る(旧 → 新が見える)。範囲外は入力欄が赤枠 + 下に理由
- 書込はモータが `disabled` のときだけ(それ以外はボタン無効 + 理由)
- `[モータに保存(type 22)…]` は確認ダイアログで書込済みの項目を表示。赤くしない。「この EL05 では 0x70xx は電源を切ると工場値に戻る(実測)」を確認文に明記する。ページ上部にも同じ内容を控えめな一行(caption)で常設し、警告色は使わない。保存しても「変更済み」の印は消えない
- `[⋯]` メニュー: ファイルへ書き出し / ファイルから読み込み(差分プレビュー付き)/ 既定値に戻す
- 読み取り専用パラメータは「状態」グループにまとめ、値を薄い色ではなく通常色で表示(読めることが重要)し、編集欄を出さない
- 運転系パラメータ(run_mode / iq_ref / spd_ref / loc_ref / limit_torque / limit_cur / limit_spd。コアの `MOTION_PARAM_KEYS` で書込を拒否するキー)も読み取り専用の行として値を通常色で見せ、編集欄は出さない。右端の空き列に薄い文字で「運転画面・出力段階で設定します」を添え、「新しい値」セルのツールチップに理由を出す(書込をログのエラーで拒否するのではなく、最初から編集できないと分かる)

### 5.3 診断ページ(T6)

セグメント `[故障] [イベントログ] [CAN フレーム] [通信統計]`
- **故障**: 発生中の故障をカードで(重大度アイコン + 名称 + 平易な説明 + 測定値と閾値 + 考えられる原因 + 対処 + [故障をリセット])。同じ故障の繰返しは件数でまとめる。正常時は 1 行「故障はありません」(緑ランプを並べない)。下に履歴表(時刻・モータ・故障・発生/解消)
- **イベントログ**: 重要度フィルタ、検索、クリア、書き出し
- **CAN フレーム**: v1 と同等(時刻・方向・ID・type・データ・デコード)。一時停止・フィルタ。等幅フォント
- **通信統計**: 送受信レート、パース失敗、タイムアウト、制御ループのジッタ

### 5.4 保守ページ(T7)

GNOME の boxed list 形式。2 グループに分ける:
- **よく使う設定**: ゼロ点を設定 / 主動上報 / 通信タイムアウト
- **注意が必要な操作**(グループ見出しに ⚠): CAN ID を変更 / CAN ボーレートを変更 / プロトコルを切り替え / CANopen・MIT プロトコルから戻す(この行だけは選択中のモータを要求しない。§12)

各行: タイトル(14 Semibold)+ 1 行説明(12 二次色)+ 影響タグ(「電源の再投入が必要」「通信できなくなる場合あり」等の小さな無彩色ラベル)+ 右端に `[設定…]`(通常ボタン)。
ダイアログ: 目的・影響・前提条件チェックボックス → 実行ボタンは動詞(「ID を 2 に変更」)。注意グループは**対象モータ ID の入力**で確定(誤操作防止)。モータが `disabled` でないと実行不可。

### 5.5 設定ページ

テーマ(ダーク/ライト/システム)、角度の表示単位、グラフ既定(時間幅・プリセット)、接続の既定値(ホスト ID)、言語(将来)、プラグイン(将来)、レイアウトの初期化。

### 5.6 接続ポップオーバー

ヘッダーの接続ボタンから開くフライアウト(角丸 8、影あり): アダプタ種別、COM ポート(CH340 を ★ 付きで先頭)+ 更新、CAN 1 Mbps / ホスト 0xFD(表示のみ)、`[接続]`(強調)。接続中は `[モータを再スキャン]` `[切断]`(通常ボタン)。

アダプタ種別は registry に登録された全トランスポート: 公式 USB-CAN(AT)/ シミュレータ / 汎用 CAN(python-can: インタフェース・チャネル・ビットレート)/ ログ再生(candump 形式のフレームログを [参照…] で選ぶ + 再生速度 + 繰り返し)。依存が無く使えない種別(python-can 未導入)は無効にして理由を薄い文字で添える。設定が足りない間(ログ未選択など)は `[接続]` を押せなくして理由をツールチップに出す。

**ログ再生は読み出し専用**: モータへ何も送らない(`ConnectionInfo.read_only`)。青の常設バナー「ログ再生中(送信しません)」(閉じられない)を出し、ステータスバーの種別は「ログ再生」。運転(モード選択・有効化・開始・JOG)、パラメータの書込・読込、保守操作は押せなくして理由を言い、`CoreBridge` もそれらの要求を拒否してログに残す(画面だけに頼らない)。ログに現れるモータはスキャン抜きで登録する。

### 5.7 出力段階 HIGH への切替ダイアログ

v1 の構成(前提チェック + 動詞ボタン + Windows の並び順)は維持。直す点: 大きな HIGH バッジ(ボタンに見える)をやめ、⚠ アイコン + 見出し。実行ボタンは琥珀系(赤にしない)。チェック項目: 「モータ本体と出力側を固定した」「周囲に人や物がない」「電源を切れる手段が手元にある」(すべて必須)。

## 9. キーボード

Pause = 非常停止(常時)。Esc = **いずれかのモータが有効/運転中のときは常に非常停止**(入力欄・ダイアログ・ポップオーバーより優先)、全モータが停止中・未接続のときは通常の Esc(編集の取消・ダイアログを閉じる)として働く(動き得るものが無いときに取消操作で非常停止がかかる煩わしさを避けるため。2026-10-02 決定)。その他: Ctrl+1..9 = ナビの順にページ切替(Ctrl+5 = スクリプト。後続のプラグインのページはナビの順に Ctrl+6 以降)、F5 = 主ボタン(有効化/運転開始)、F6 = 運転停止、JOG モードで ← / → 長押し = JOG(インスペクタにフォーカスがあるとき)、Ctrl+R = 記録開始/停止、グラフにフォーカスがあるとき Space = 一時停止。

## 11. Bridge / ViewModel の変更(UI を状態モデルに合わせる)

- `MotorViewState.ui_state: Literal["offline","disabled","enabled","running","fault"]` を追加
- `enable(ids, run_mode)` は有効化時のモードを受け取る / `disable(ids)` を追加(旧 `stop`)/ `start_controller` は `enabled` からのみ / `stop_controller` は運転停止(有効のまま)
- `estop_latched() -> bool`、`estop_changed = Signal(bool)`、`release_estop()` を追加
- `fault_details(motor_id) -> list[FaultDetail]`(名称・説明・測定値・閾値・原因・対処・件数・発生時刻)
- DemoBridge をこの状態モデルどおりに動かす(`--start-offline` で未接続から開始)

段階 1 での実装時に加えた(上記に含まれない)もの:
- `ConnectionInfo.lost: bool`(通信断)/ `Bridge.reconnect()`(直前の設定で再接続)/ `Bridge.inject_comm_loss()`(モック専用)
- `Bridge.set_power_tier("high")` は、非常停止ラッチ中・未接続・有効なモータがあるときは拒否する
- (phase4-fb-X)`Bridge.tool_finished = Signal(str, int, bool, str)`(ツール名・モータ ID・成功か・結果またはエラー文)を `run_tool` の完了で発行する。
  運転ページの「原点に設定」が結果をトーストにするために使う。`PowerLimits` に `kd_negative_max` / `friction_comp_max`(MIT のホスト側項の上限)を追加。
  `ParamForm` のフィールド metadata に `neg_limit`(負側の下限を出力段階の上限キーで動的に制限)と `hint`(ツールチップへ足す補足の tr キー)を追加
- `FaultDetail` は `key, name, description, measured, threshold, unit, causes, remedy, count, first_t, last_t`
- 運転停止後・有効化直後は「保持」(`enabled` のまま)。UI 状態の導出は `MotorViewState.ui_state` を信頼する

段階 3(統合)で加えた(Phase 3 の CoreBridge でも実装する):
- `ChannelInfo`: 電圧チャネル `m{id}.vbus`(`kind="vbus"`、単位 V)を `available_channels()` / `scope_data()` に追加。運転ページの電圧グラフは状態の更新から自前の履歴を持たず、このチャネルを読む
- `BusStats.parse_errors: int = 0` / `timeouts: int = 0`(接続してからの累計)。診断の通信統計が表示する。DemoBridge は通信断の再現で増やす
- `ShellApi`: `navigate(page_id, view=None)`(ページが `show_view(view)` を持てば渡す。バナー [原因を確認] → 診断の故障、運転ページのイベント行 → 診断のイベントログ)と `settings() -> QSettings | None`(`user_data/ui_state.ini`。ページの区画の幅は `layout/` グループ、設定ページの値は `prefs/` グループ)
- `HoldButton.press()` / `release(reason="release")`(キーボード・テスト用の公開 API。QSS の `min-height` は `variant="hold"` で JOG の高さに合わせる)
- 診断ナビの赤い点は診断ページの `unseen_changed(bool)` で決める(発生中の故障を故障ビューで見たかどうか)

## 12. 決定事項と保留

- 非常停止は**即時無効化(停止カテゴリ 0 相当)**とする。重力負荷のある用途はスコープ外のため、減速してから無効化する方式(カテゴリ 1 相当)は保留
- 運転停止(非常停止ではない)は、速度・電流は 0 へ、位置・MIT は現在位置保持へ移行して `enabled` に戻る
- メニューバーは廃止(ヘッダーの ⋯ に集約)
- v1 のライトテーマも v2 トークンで作り直す
- 状態変化の時間帯表示(グラフ下の帯)、ステップ応答の単発取得、2 点 Δ カーソルは Phase 4 の Scope 強化で行う
- モック(DemoBridge)での CSV 記録(運転ページの `⏺ 記録`)は、状態の更新(約 60 Hz)をその都度サンプルしている。Phase 3 で本物のテレメトリバッファ(`core/telemetry`)から取る方式に差し替える(列は変えない)
- 2台連動は、モックでは「リーダの位置を MIT 目標としてフォロワへ書き込み続ける簡易版」(Kp = 0 のリーダ + 追従するフォロワ)。専用のコントローラは Phase 4 のバイラテラル制御で作る
- 「CANopen・MIT プロトコルから戻す」は、その状態のモータがスキャンで見つからないことが多いため、選択中のモータを要求しない。接続中で、有効・運転中のモータが無く、非常停止がラッチされていないときに押せ、対象のモータ ID(0〜127)といまのプロトコルはダイアログで入力する
- (phase4-fb-X)位置モードの目標の基準の既定は「1 回転内(最短)」。多回転の入力は残す(従来の挙動)。MIT には基準の選択を付けない(目標は多回転のまま)
- (phase4-fb-X)「原点に設定」は運転ページの位置カードから行う(保守ページにもある同じ操作)。有効・運転中は停止 → 無効化してから実行する(type 6 は停止中だけ効く)
- (phase4-fb-X)電流チャネル: `m{id}.current`(実測 iqf)と `m{id}.cmd_current`(指令 cmd.cur、単位 A、グラフ段 `current`)を `available_channels()` / `scope_data()` / 記録 CSV に足す。グラフは「すべて」の表示で電流の段を出す(それ以外のプリセットには出さない)
- (phase4-fb-X)ステップ応答の行・帯・凡例の高さは常に確保し、通常の操作でプロットの高さを変えない
- 運転ページのモニタとインスペクタの境(区画境界)はドラッグで動かせる(インスペクタ 360〜520 px)。幅は `layout/operate/inspector_w` に保存し、設定の「レイアウトの初期化」で戻す
- テーマ「システム」は選択そのものを `prefs/theme_mode` に保存し、起動時に OS の配色へ合わせる(配色の結果は従来どおり `theme` に保存)
